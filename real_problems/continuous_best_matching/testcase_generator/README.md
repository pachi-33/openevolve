# 测试用例生成

## 问题描述

有一个二分图 -> (U, V, E)。其中，U是左侧顶点、V是右侧顶点，E是U到V的边集合。
|U| 大于 |V|，且 |E| == |U|*|V|
E中的每条边都有一个大于等于0的边权。
经典的KM算法可以求解：二分图匹配下的最大权值之和的最优匹配。
本场景不同之处在于，U是一个有偏序性的集合。且，|U| 大于 |V| 则必然有左侧顶点没有匹配的对向顶点，我们把没有匹配的点看作断点，
沿着U的顺序看，有断点把U切分成N个集合，即 二分图 (U, V, E) 被拆成了N个子图。现在我们定义 权值之和最大的子图为目标子图，
要求解一种匹配，使得目标子图的总权值最大。

## 判例的问题规模

|U| 的范围 [2~12]
|V| 的范围 [2~10]
E 的边权取值范围 [0~10^6]
总判例数量 约 100个，要求覆盖所有边界情况

## 输出

描述测试用例生成器的输入

### 用例存放位置

real_problems/continuous_best_matching/testcase_generator/testcases.json

### 用例格式

测试用例使用 JSON 格式存储，包含一个测试用例数组：

```json
{
  "testcases": [
    {
      "id": "test_001",
      "description": "小规模基本测试",
      "input": {
        "n": 3,
        "m": 2,
        "weights": [
          [1, 2],
          [3, 4],
          [5, 6]
        ]
      },
      "expected_output": {
        "matches": [[0, 0], [2, 1]],
        "max_segment_weight": 7
      }
    }
  ]
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 测试用例唯一标识 |
| `description` | string | 测试用例描述（边界情况、特殊场景等） |
| `input.n` | int | U 集合的大小 (\|U\|)，范围 [2, 12] |
| `input.m` | int | V 集合的大小 (\|V\|)，范围 [2, 10]，且 m < n |
| `input.weights` | list[list[int]] | 边权矩阵，大小为 n×m，weights[i][j] 表示 U_i 到 V_j 的边权，范围 [0, 10^6] |
| `expected_output.matches` | list[list[int]] | 最优匹配结果，每个元素是 [u, v] 表示 U_u 匹配到 V_v |
| `expected_output.max_segment_weight` | int | 最优匹配下最大子图的权值之和 |

#### 问题定义说明

- U 集合是有序的（按索引 0, 1, 2, ..., n-1），具有偏序性
- 匹配规则：每个 V 中的顶点最多匹配一个 U 中的顶点，每个 U 中的顶点最多匹配一个 V 中的顶点
- 由于 n > m，必然有 n-m 个 U 顶点无法匹配，这些未匹配点形成**断点**
- 断点将 U 分割成若干个连续的子集，每个子集与 V 形成一个子图
- 对每个子图，计算其内部匹配边权之和
- 目标：**最大化所有子图中权值之和的最大值**

#### 边界情况覆盖要求

测试用例需要覆盖以下场景：
1. **最小规模**: n=2, m=2
2. **最大规模**: n=12, m=10
3. **m=2 最小情况**: 验证算法在最小子图情况下的表现
4. **全零边权**: 所有边权为 0
5. **全最大边权**: 所有边权为 10^6
6. **稀疏匹配**: 存在多个断点的场景
7. **连续匹配**: 无断点（全部 U 匹配到 V）- 虽然 n>m 不可能全部匹配，但可以尽可能连续
8. **单个断点**: 只有一个断点的场景
9. **多个断点**: 多个断点分散的场景
10. **权值递增/递减**: 边权有规律变化
